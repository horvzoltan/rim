# rim

A small, fast code editor written in Rust (egui). It has no built-in terminal, by design.

## Features
- Find in Files (`Ctrl+Shift+F`), like IntelliJ's: results appear as you type, with a highlighted preview of the
  selected match; arrows move, Enter opens it; match case and whole words toggles
- File explorer (git-status colors, new/rename/move to trash), tabs, quick open (`Ctrl+P`), command palette (`Ctrl+Shift+P`)
- Syntax highlighting for ~200 languages (syntect + bat's syntax set)
- Language servers installed with one click (Settings → Language Servers), for ~30 languages
- Language server features: diagnostics, completion (`Ctrl+Space` / as you type), hover (mouse or `Ctrl+K`), go to definition (`F12` / `Ctrl+click`), formatting
- Auto-imports: completing a name from another module adds its import (TypeScript, Rust, …), and quick fixes
  (`Ctrl+.`) offer the server's fixes for the problem under the cursor, such as "Add import from …" or
  "Add all missing imports"
- External formatters (prettier, rustfmt, ruff, gofmt, clang-format, stylua), with optional format on save; a project-local `node_modules/.bin/prettier` is preferred
- Git: status, stage/unstage/discard, commit, diffs, branch checkout/create, pull/push/fetch, log, gutter change markers
- Find in file (`Ctrl+F`), go to line (`Ctrl+G`), toggle comment (`Ctrl+/`), auto-indent
- Claude Code in a side panel (`Ctrl+L`): streaming chat, tool cards, inline diffs, approvals, session history
- Project graph (`Ctrl+Shift+M`): a zoomable map of every folder and file joined by their imports, with a
  one-line explanation of each part (from its comments, or generated by Claude on demand)
- Optional vim motions (off by default): toggle in Settings (`Ctrl+,`) or with "Preferences: Toggle Vim Motions"
- Themes: tokyonight, catppuccin (mocha/latte), gruvbox (dark/light), kanagawa, nord, onedark, rose-pine, everforest

## Usage
    cargo build --release
    ./target/release/rim [folder-or-file]

Needs Rust (https://rustup.rs). Runs on Linux and macOS.

### Running on macOS
    xcode-select --install                                           # Apple's command-line tools (compiler, linker, git)
    curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh   # Rust, then open a new terminal
    git clone git@github.com:horvzoltan/rim.git && cd rim
    cargo build --release
    ./target/release/rim ~/path/to/project

Works on Apple Silicon and Intel Macs. Optionally put it on your `PATH` with `cargo install --path .`, then run `rim .`.
- Started from the Dock/Finder, rim takes `PATH` from your login shell, so it finds language servers, formatters,
  `node` and `claude` the same way a terminal does.
- Shortcuts written as `Ctrl` below are `Cmd` on macOS (e.g. `Cmd+P`, `Cmd+Shift+P`, `Cmd+S`).
- The config file lives in `~/Library/Application Support/rim/config.toml` instead of `~/.config/rim/`.

Settings live in `~/.config/rim/config.toml`. Open it with "Preferences: Open config.toml"; saving the file reloads it.
Formatters are ordinary programs on your `PATH`, configured per file extension in that file.
Your `[formatters]` and `[[language_servers]]` entries add to the built-in ones (same extension or name overrides;
`ext = []` turns a formatter off). Changing settings in the app only rewrites those keys, so comments and layout in the
file are kept, and a config.toml with errors is never overwritten.

Saving is safe: files are written to a temporary file and renamed into place (permissions kept), CRLF files keep
their line endings, and if another program changed the file since you opened it, rim asks before overwriting.

## Language servers
Open **Settings → Language Servers** (`Ctrl+,`, or "Preferences: Language Servers"), pick a language and click
**Install**. rim installs the server into its own folder (`~/.local/share/rim/servers`, on macOS
`~/Library/Application Support/rim/servers`): no sudo, nothing global, and **Uninstall** deletes the folder. When a file
has no server, the status bar offers "Install … support".
- Covers Rust, TypeScript/JavaScript/React, Python, C/C++, Go, Lua, Zig, HTML, CSS, JSON, ESLint, Tailwind, Vue,
  Svelte, Angular, YAML, TOML, Markdown, Bash, Dockerfile, Java, Kotlin, C#, Ruby, PHP, Swift and Elixir.
- Servers come from their official GitHub releases, or through npm / go / gem / dotnet for those published that way
  (rim says what's missing, e.g. "Needs Node.js"). Swift's comes with Xcode or the Swift toolchain.
- Which server runs: your own `[[language_servers]]` entry in config.toml, else rim's installed copy, else one found
  on `PATH`. Turn any server off with its **Enabled** switch (`disabled_language_servers` in config.toml).
- Add-ons (ESLint, Tailwind CSS, Angular) run next to the file's main server and add their own problems.
- **Check for updates** compares with the newest npm / GitHub release; install, update and uninstall take effect
  without restarting rim.

## Settings
`Ctrl+,` opens a small settings dialog: vim motions, format on save, indentation, font size and theme.
Everything is also in `~/.config/rim/config.toml` (e.g. `vim_mode = true`).

## Vim motions
When enabled, each tab starts in normal mode; the status bar shows the mode.
- Modes: normal, insert (`i a I A o O s S c...`), visual (`v`), visual line (`V`), command line (`:` `/` `?`)
- Motions: `h j k l w W b B e E ge 0 ^ $ gg G {n}G f F t T ; , % { } n N * # _ + -`, `Ctrl+d/u/f/b`, with counts
- Operators: `d c y > <` with motions, doubled for lines (`dd cc yy >>`), and text objects (`iw aw i" a" i( a( i{ a{ i[ a[ ip ap`)
- Other: `x X D C s S Y p P J r ~ u Ctrl+r .` (dot repeat), one shared register (yanks also go to the system clipboard)
- Ex commands: `:w :q :q! :wq :x :{line}`; `ZZ` / `ZQ`
- `Ctrl+F` / `Ctrl+B` page down/up in normal mode (Find and the sidebar toggle stay available from insert mode or the palette)
- Not supported: macros, marks, named registers, visual block, regex substitute (`:s`)

## Project graph
`Ctrl+Shift+M` (or the network icon in the sidebar) replaces the editor with a map of the project: every file is a
circle (bigger for longer files), every folder a tinted region, and every import a line. Scroll to zoom, drag the
background to pan, drag a circle to move it, click one to see what it is, double-click to open it in the editor,
`Esc` to go back. Zoomed out you see the folders; zoomed in, file names and icons appear.
- **Imports** come from a quick text scan of `use`/`mod` (Rust), `import`/`require` (JS/TS), `from … import`
  (Python), `#include "…"` (C/C++), `import` (Go, via `go.mod`) and `@import`/`@use` (CSS/SCSS), resolved to
  files in the project. Unresolved ones (crates, packages, system headers) are counted as external.
- **Descriptions** start from the file's own comments (`//!`, a leading `/** */` or `#` block, a Python docstring)
  and a folder's `README.md`. *Describe with Claude* asks the local Claude Code CLI for a 1-2 sentence summary of
  the selected file or folder; *Describe all* does it for everything, one at a time, in the background.
  Summaries are cached in `<project>/.rim/graph.json` keyed by the file's contents, so a file is only summarized
  again after it changes. You may want `.rim/` in your `.gitignore`.
- The filter box dims everything whose path doesn't match; `Enter` jumps to the first match.
- Projects with more than 5000 files are shown as folders only (`[graph] max_files` in config.toml);
  `[graph] describe_model` picks the model for summaries (the `[claude]` model otherwise).

## Claude
`Ctrl+L` opens the Claude panel (and moves focus between chat and editor). It drives the local **Claude Code** CLI, so your login,
models, `CLAUDE.md`, MCP servers, skills and permission rules work exactly as they do in a terminal.
- **Setup:** rim finds Claude Code on `PATH`, in the usual install locations, or in the VS Code extension's bundled copy
  (override with `[claude] path = "…"`). When it is missing, or only the extension's copy is there (that path changes with
  every extension update), the panel offers *Install Claude Code*, which runs the official installer into `~/.local/bin`.
  If you are already signed in from VS Code or a terminal, rim uses that login.
- **Signing in:** if you are signed out, the panel shows a Sign in banner: it opens your browser, you paste the code the page shows,
  and you're in. The Account menu shows who is signed in and has Sign out (which also signs out VS Code and terminals).
- **Context:** your open file and selection are shared with each prompt (untick the box under the prompt to stop). `@` mentions a file.
- **Approvals:** edits and commands show up as cards with a diff or the command, and wait for Allow / Deny.
  Modes: ask before edits, edit automatically, plan mode.
- **Models:** the picker under the prompt lists every model your account can use (Claude Code reports them), with the
  default first. The `⋯` menu sets effort (low → max), thinking, fast mode, the output style, and whether to switch models
  automatically when a message is flagged; these are remembered in config.toml and take effect on the next turn.
- **Images:** paste a screenshot with `Ctrl+V`, drop an image file onto the panel, or use the 🖼 button. PNG, JPEG, GIF
  and WebP; big pictures are scaled to 2000 px. Attachments show as thumbnails before and after sending.
  (On Wayland, pasting reads the clipboard with `wl-paste` from the wl-clipboard package.)
- **Also:** Esc stops a running turn, History resumes earlier conversations, files Claude changes reload in the editor,
  `⋯ → Export conversation` saves the chat as text, and `⋯ → Account & usage` shows your plan's limits and this session's cost.
- **Slash commands:** type `/` for the list Claude Code reports (built-ins like `/compact` and `/review`, your skills,
  plugins); arrows pick, Tab or Enter completes, and the message is sent as typed so the CLI runs it.
- **Not yet:** MCP management menus and Claude's own diff-review tab inside the editor.

## Development
    cargo test                                   # ~200 tests, headless (no window needed)
    cargo test -- --ignored                      # also talks to real rust-analyzer / Claude Code (uses a little plan usage)
    cargo test --release bench_frames -- --ignored --nocapture   # frame times on 5k–50k line files

Large files stay responsive: highlighting parses lazily and only colours the visible lines, and git status,
commits, project search and file listing run in the background.

File-type icons come from [nvim-web-devicons](https://github.com/nvim-tree/nvim-web-devicons) (MIT) and the
[Nerd Fonts](https://www.nerdfonts.com) symbols font (MIT), cut down to the glyphs rim uses. To update them:
`tools/gen_file_icons.py path/to/SymbolsNerdFont-Regular.ttf` (needs fonttools). Licences are in `assets/fonts/`.
